四条关键链路

1

开通成员

公司管理员提交 → api 校验席位数 → POST /users 建中转站账号并绑专属分组 → 回写 tenant_members.relay_user_id。

2

分配额度

先校验公司池剩余 → POST /users/:id/balance（带幂等键）→ 记 quota_allocations。失败重试不会重复加钱。

3

关键词流转

客户端提交 → 待审 → 公司管理员审（平台管理员可审全局词）→ 版本号 +1 → 客户端按 since 拉增量。

4

用量归集

每日 cron 拉 /users/:id/usage 落到 usage_snapshots；看板只读本地表，不实时打中转站。

三条硬边界

不代理算力 客户端直连 gateway，evc-admin 只处理业务数据。链路短、故障面小，也不会成为带宽瓶颈。
管理密钥只在服务端 受限密钥仅存 evc-admin 环境变量，公司管理员永远看不到，也无法直接调用中转站管理接口。
tenant_id 只从 token 取 绝不读请求体里的租户参数；所有查询走带租户过滤的 Repository，并配跨租户越权测试。
evc-admin · 架构草案 v1 另需确认：中转站自助注册是否关闭，否则员工可绕过公司归属自行注册。
